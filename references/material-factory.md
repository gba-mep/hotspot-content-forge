# 小红书物料工厂（海报/视频流水线）

> 本文件随本仓库发布，配方经实战验证。

## When to Use
- 新品发布/版本更新需要封面海报、功能介绍视频

## 视觉风格选择（先预览后定稿，不默认蓝图）
- 出物料前先给用户选风格，按内容线推荐 2-3 个风格让用户点名，不要每篇都用蓝图风格
- **图文笔记默认用轻亮配方**：底 #f6f8fa / 墨 #1f2328 / 辅助 #656d76 / 白卡+描边 #d0d7de / 蓝 #0078d7 / 绿 #217346 / 红 #e5484d 仅裁决处（每卡≤2）；白卡=圆角+柔投影+描边，不做旧无纹理
- 做旧/复古工程质感（灰米珐琅板、白珐琅板+窗光+擦痕幽灵等）只留给「旧档案/复古工程」叙事主题。三色墨语义可复用：石墨黑=规则/蓝=度量/红=裁决且每帧≤3处；钉板纸卡=投影+微旋转+红磁钉；裁决用红章
- **CJK 字体坑**：NotoSansCJK-*.ttc 是 JP/KR/SC/TC/HK 五字体打包，`ImageFont.truetype(path, sz)` 不传 index 默认取 JP 日文面，「门/关/复/画」等简体字骨架会变形；中文物料一律 `ImageFont.truetype(path, sz, index=2)`（SC 面）
- **多面板对比卡用子画布配方**：每个面板先在独立小画布（如 520x300）里画完图形，再 resize 贴入大卡面板位——直接在整卡坐标系里手写多组相对坐标，标注线/标题栏/信心行必互相压线（实测返工 3 轮）；面板底部固定预留一行信心/注释文字位，图形元素一律不越过该线
- **示意图必须标明「示意图」**：凡非真实截图/实拍的图形（示意构件、流程图），卡面徽章注明「示意图」，不得做成实拍质感冒充——避免「AI 冒充实拍」合规风险
- **同一物料目录多套风格脚本禁止写同名输出**：后跑的会静默覆盖先跑的，vision 复检看到旧风格会误判脚本未生效；每套脚本独立文件名（如 cover_blueprint.png / cover_briefing.png），或定稿只跑最后一个脚本

## 海报模板（3:4 1242x1660）
- 结构：顶部大标题(72pt)+副标(34) → 产品帧A → 产品帧B → 底部白卡卖点条(2x2)
- 轻亮版配色：背景 #f6f8fa，墨色 #1f2328，辅助 #656d76，卡片白+描边 #d0d7de，保留产品色块（绿 #217346/蓝 #0078d7）
- 深色版仅作备用封面；主推轻亮版（与视频同风格）

## 视频模板（竖版 1080x1920, 15fps）
- 结构：开场卖点卡 → 主功能演示 → 新功能特写 → 次功能速览 → 结尾双卡（梗+点菜 1/2/3 数字卡）
- 内部按 720x1280 绘制，输出前 `resize((1080,1920), Image.LANCZOS)` 升采（平台要求 1080P）
- ffmpeg：`-framerate 15 -i f%04d.png -c:v libx264 -pix_fmt yuv420p -crf 18`（yuv420p 必加否则部分播放器黑屏）

## 叙事短视频脚本模式
- 结构：`SCENES = [(t0, t1, draw_fn), ...]` 场景表 + `render_frame(f)` 按 t 落到对应场景算 p=(t-t0)/(t1-t0) 传入；每帧独立重画（网格+固定元素重画一遍，天然无残影）
- vision 终检最常抓到的两个 bug：①标题栏/卡片里最小那行字贴框底被裁切（每轮都在小字行上）；②结尾点菜卡出现阈值太晚（>0.75 的 p 阈值在短场景里只剩不到 1 秒露出，提到 ≤0.6）；修完重渲后**必须重新抽帧复检**——帧同名覆盖渲染，不重抽会把旧帧当新帧误判
- 混音后验证两步：`ffprobe -select_streams a` 确认音轨存在；响度用 `ffmpeg -i 成品 -af ebur128 -f null - 2>&1 | tail -8` 看（grep "Integrated loudness" 会抓到流开头的 -70 初始行误判）
- 重渲时**不要 rm 帧目录**：同文件名覆盖渲染即可，确保帧总数没变
- BGM 选曲按情绪桶查曲库（叙事/趣味用 playful 桶），CC-BY 曲目署名行写进 note.md 随笔记发布

## PIL 模板调用坑
- `add_film_grain(img, strength)` 的 strength 是小数比例（默认 0.02），传 8 会输出整幅雪花噪声——vision 复检只见纯噪点，全篇重渲
- `Layout_Terminal` 的 code_lines/output_lines 收纯字符串列表（非 (str,color) 元组）；标题块下方有一行硬编码 `$ python3 demo.py --mode=demo` 样式占位，无法去除
- `Layout_TypoLaunch` 的 slogan 过长（>18 字符）会从右侧截断——用短名，全名放 kicker
- `Layout_Chart` 标题 >20 字也会右侧截断，自绘条形卡更稳

## 出片前自动检查（每次必跑，顺序执行）
1. **敏感词 grep**：对生成脚本 grep `伪装|骗|老板|最|第一|外挂|破解` —— 一个词藏在任何角落（开场标题/卖点卡/弹窗正文/结尾卡）都可能导致笔记被拒审
2. **豆腐块检查**：文案禁用 emoji 和特殊符号（PIL 的 NotoSansCJK 不含 emoji，✗✓👇❌ 这类符号同样必出豆腐框）——需要图形感就用 ×/√/文字括号或自绘形状；每轮 vision 终检都专门问一句「有无豆腐框」
3. **超宽+超高检查**：d.textlength() 逐行实测每条绘制文字宽度 ≤ W-80（不止标题——正文字号小但行会很长，38pt×16 字在 720px 画布就贴边裁切）；实测：7 字@96pt 衬线在 720px 竖版画布左右贴边裁切，场景大字超 5 字一律拆两行（每行 ≤4 字、字号 ≤120），超了缩短文案不缩字体；多行文字框还要实测**高度**：字号 px≈pt 数值，框高=行数×行距+上下边距，最后一行底部超出框必裁切（小字行比大标题更容易被忽略）
4. **残影检查**：逐帧动画中位置变化的文字必须先矩形擦除旧字再写新字
5. **vision 终检**：抽 2-4 个代表帧交视觉模型复检，逐帧问「文字完整？无重叠？无豆腐？」

## BGM/音频素材源（实测）
- **FreePD 已关站**，不再是 CC0 首选；Pixabay CDN 在沙箱不可达、archive.org 沙箱完全不通——这三个别再试
- **Incompetech**（Kevin MacLeod）是主力：官方目录 1443 首含情绪/流派/BPM，CC-BY 4.0，发布时须附署名清单；官网直连仅 ~10KB/s，可走 GitHub 镜像库 raw 单文件直连
- 取大仓库文件清单的三条死路：git clone 大包 SSL 超时、GitHub API 限流、jsdelivr data API 对 >50MB 包一律 403。可行路：① 仓库网页版 tree 页抓取后正则提 blob 链接拿清单；② 下载用 raw 单文件直连，raw 慢/间歇失败时换 `cdn.jsdelivr.net/gh/<user>/<repo>@<branch>/<file>` 兜底（CDN 出文件与 data API 是两套限制，包超 50MB 只封目录 API 不封文件 CDN）
- 零负担替代：原创合成曲（ffmpeg 合成垫底音量+淡出），发布无需署名
- 建议自建本地曲库目录（按情绪桶分类 + catalog.csv + 署名清单），新片直接从曲库选，不再重复下载；TTS 口播+BGM 混音配方见 references/video-maker.md

## 交付规范
- 成品统一存放在项目自有 materials/ 目录；目录在 git 仓库内才 commit，非仓库直接通过媒体通道发出
- 帧目录用完即删（/tmp 会被重置，成品不进 /tmp）
- 每次物料产出后把新坑 patch 回本技能
