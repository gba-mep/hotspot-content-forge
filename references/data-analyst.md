# 小红书数据读数与归因流程

> 适用场景：拿到小红书数据后台截图（笔记数据 / 下载量 / 小工具使用量），需要标准化地读数、诊断账号活性并产出下一步动作；也可用于每周巡检汇总趋势。

## 流程总览

**读数 → 活性诊断 → 三个动作 → 归档**

## 1. 读数（先报原数，再谈分析）

- 用视觉模型逐笔记提取：浏览量、点赞、收藏、评论；如有独立分发物（如 Skill / 小工具），另取下载量。
- 原则：先把原始数字完整报出来，再做分析；禁止凭印象描述数据。
- 对照历史读数时，使用台账中的历史基准做横向比较（基准本身不入公开文档，维护在自己的笔记台账里）。

## 2. 活性诊断（阈值固定，按漏斗顺序看）

漏斗顺序：**点击率 → 完读率 → 收藏率 → 评论 → 转粉**。

| 指标 | 阈值 | 诊断结论 |
| --- | --- | --- |
| 图文点击率 | < 2.5% | 首屏失败；改封面/标题优先于一切内容归因 |
| 赞藏率 | < 2% | 内容不吸引，先改封面标题 |
| 完读率 | < 40% | 开头钩子弱 |
| 收藏率 | < 5% | 干货不足 |
| 评论数 | = 0 | 漏斗最大破绽，优先级高于一切流量动作 |
| 浏览爬升斜率 | 趋平 | 平台不推第二波，需要互动撬动 |

**评论归因顺序（重要教训）**：发现 0 评论时，先查账号评论权限设置（如「仅关注者可评」之类的开关），再归因内容，最后才考虑互动动作。平台设置类乌龙优先于内容归因——曾出现因权限设置导致长期 0 评论、被误诊为内容破绽的案例。

## 3. 三个固定动作（决策树）

```
数据不达标
├─ 有 0 评论笔记？
│   └─ ① 暖场：每篇各发一条提问式评论
│        （从 0 到 1 比从 1 到 10 值钱）
├─ 点击率 / 赞藏率不达标？
│   └─ ② 改封面：24h 内改 2-3 次是安全的；
│        优先验证过的封面基因：翻车叙事 + 真场景照片 + 数字反差；
│        封面重做走现成的封面模板库与生图管线，不手写绘图脚本
└─ 评论区点菜（呼声最高的功能）？
    └─ ③ 出货候命：24h 内给方案，兑现「听劝」人设
```

## 4. 归档

- 数据与结论追加到该项目的需求清单 / 笔记台账。
- 跨笔记的趋势分析留给每周巡检，不逐篇追。

## 基准维护

历史单篇读数、账号级对比基准（最高互动率样本、近期样本等）属于敏感运营数据，不入本文档；自行维护在私有台账中，诊断时按第 2 节阈值对照即可。
